## 概览
本文档定义了游戏策划书的格式规范和内容要求。
适用对象为可解压即玩的 H5 单机游戏：品类标签取自 `game_genres.md` 的 9 类；数值规模按本作玩法繁简取用，简单小游戏不强求等级、经济、装备等重度系统；资源能用 Canvas/CSS/文字/emoji 实现的优先标注无需出图，需出图的统一用 PNG（不使用 PSD），音效默认只规划失败音和胜利音。

## 1. 游戏概述
**必需内容：**
- 游戏名称
- 游戏品类（参考 `game_genres.md`）
- 游戏标签（3-5个关键词）
- 一句话介绍（游戏核心卖点）
- 游戏背景故事（简述世界观和故事背景）
- 目标平台（PC/移动端/主机/多平台）
- 目标上线时间

**格式要求：**
```
# 游戏名称：[名称]
# 品类：[主品类] - [子品类]
# 标签：[标签1] [标签2] [标签3] [标签4] [标签5]

## 一句话介绍
[核心卖点和玩法亮点]

## 游戏背景
[世界观设定和故事背景概述]
```

## 2. 目标人群
**必需内容：**
- 核心玩家画像（参考 `target_audiences.md`）
- 年龄段分布
- 游戏经验（新手/休闲/核心/硬核）
- 预期游玩时长（单次/总计）
- 消费能力评估

**格式要求：**
```
## 核心玩家画像
- **主要人群**：[人群类型1]（占比约X%）
- **次要人群**：[人群类型2]（占比约Y%）
- **扩展人群**：[人群类型3]（占比约Z%）

## 人群特征分析
- **年龄段**：[年龄段1]-[年龄段2]为主
- **游戏经验**：[经验水平]
- **游玩习惯**：[单次时长]，[总计时长预估]
```

## 3. 核心玩法
**必需内容：**
- 核心玩法循环（输入→反馈→奖励）
- 主要玩法机制（2-5个核心机制）
- 操作方式（鼠标/键盘/触屏，需同时兼容鼠标与触摸）
- 胜负与结算条件（如何获胜/失败、结算反馈与奖励）
- 乐趣来源分析（挑战/探索/收集/社交等）
- 难度曲线设计

**格式要求：**
```
## 核心玩法循环
1. 玩家[操作]
2. 系统[反馈]
3. 获得[奖励]
4. 激发[新目标]

## 主要玩法机制
### 机制1：[名称]
- **描述**：[机制说明]
- **触发条件**：[何时触发]
- **效果**：[对游戏的影响]

[...]

## 操作方式
- [平台1]：[操作方式说明]
- [平台2]：[操作方式说明]

## 胜负与结算
- **获胜条件**：[如何通关/达成目标]
- **失败条件**：[如何失败/结束]
- **结算反馈**：[结算界面、奖励、评分、重玩引导]

## 乐趣来源
- [乐趣类型1]：[具体实现]
- [乐趣类型2]：[具体实现]
```

## 4. 数值体系
**必需内容：**
- 核心数值列表（角色、装备、技能等）
- 数值增长模型（等级、经验、属性成长）
- 经济系统（货币来源/消耗/平衡）
- 难度数值设计（敌人属性、关卡难度）
- 平衡性考虑

**格式要求：**
```
## 核心数值体系
### 角色属性
| 属性名称 | 初始值 | 最大值 | 作用说明 |
|---------|--------|--------|----------|
| HP | 100 | 1000 | 生命值 |
| MP | 50 | 500 | 魔法值 |
| [...] | [...] | [...] | [...] |

### 数值成长模型
- **经验曲线**：[公式或描述]
- **属性成长**：[成长规则]
- **等级上限**：[最高等级]

## 经济系统
### 货币体系
- **[货币1]**：[获取方式]、[消耗用途]、[平衡策略]
- **[货币2]**：[获取方式]、[消耗用途]、[平衡策略]

### 资源平衡
- [资源1]的产出/消耗比约为 [比例]
- [资源2]的产出/消耗比约为 [比例]

## 难度数值
- **敌人属性公式**：[公式]
- **关卡难度曲线**：[描述]
```

## 5. 美术风格
**必需内容：**
- 整体美术风格定义
- 色彩方案（主色调、辅助色、强调色）
- 角色设计要求（风格、体型、服装特征）
- 场景设计要求（环境风格、关键元素）
- UI/UX设计方向
- 美术资源需求清单（须标明每项是"需出图(PNG)"还是"用 Canvas/CSS/文字/emoji 实现，无需出图"；简单小物品、小图标、子弹、普通障碍优先后者）
- 音效需求（默认只规划失败音和胜利音，其他音效仅在用户明确要求或核心玩法强依赖时写入）

**格式要求：**
```
## 美术风格定义
- **整体风格**：[风格关键词，如：像素风、卡通渲染、写实风等]
- **参考作品**：[1-2个参考游戏名称]

## 色彩方案
- **主色调**：[颜色代码] - [使用场景]
- **辅助色**：[颜色代码] - [使用场景]
- **强调色**：[颜色代码] - [使用场景]

## 角色设计要求
### 主角设计
- **风格**：[风格描述]
- **体型特征**：[描述]
- **服装特点**：[描述]
- **标志性元素**：[1-2个关键视觉特征]

### 敌人设计
- **敌人类型1**：[设计要求]
- **敌人类型2**：[设计要求]

## 场景设计要求
### 场景1：[场景名称]
- **环境风格**：[风格描述]
- **关键元素**：[主要视觉元素]
- **氛围营造**：[氛围描述]

[...]

## UI/UX设计
- **主界面风格**：[描述]
- **交互原则**：[设计原则]
- **信息层级**：[信息架构]

## 美术资源清单
| 资源类型 | 数量 | 规格/格式 | 备注 |
|---------|------|----------|------|
| 角色立绘 | X | [尺寸] PNG | [说明] |
| 场景背景 | X | [尺寸] PNG | [说明] |
| 道具图标 | X | [尺寸] PNG | [说明] |
| UI元素 | X | [尺寸] PNG | [说明] |
```

## 6. 系统设计
**必需内容：**
- 核心系统列表（战斗系统、任务系统、升级系统等）
- 每个系统的功能描述
- 系统间交互关系
- 创新点说明

**格式要求：**
```
## 核心系统
### 系统1：[系统名称]
- **功能描述**：[系统作用]
- **核心功能**：
  - [功能1]：[描述]
  - [功能2]：[描述]
- **与其他系统的交互**：[说明]

[...]

## 系统创新点
- [创新点1]：[描述]
- [创新点2]：[描述]
```

## 7. 关卡设计
**必需内容：**
- 关卡结构（章节/区域划分）
- 关卡节奏设计
- 教学/引导设计
- 里程碑节点

**格式要求：**
```
## 关卡结构
### 第一章：[章节名称]
- **关卡数量**：X关
- **核心目标**：[目标]
- **主要挑战**：[挑战类型]

### 第二章：[章节名称]
[...]

## 关卡节奏
- **前期**：[节奏和内容]
- **中期**：[节奏和内容]
- **后期**：[节奏和内容]

## 教学设计
- **新手引导**：[引导内容和方式]
- **核心机制教学**：[教学安排]
```

## 8. 边界与异常处理
**必需内容：**
- 数值边界（最大/最小值、溢出、除零、负数）
- 交互边界（连点、非法操作、画面外点击）
- 状态边界（暂停/失焦/重开/异常状态切换）
- 资源加载失败兜底（图片缺失降级为 Canvas 几何图形，音效缺失不阻塞流程）
- 存档/进度异常（如使用本地存储时的读写失败处理）

**格式要求：**
```
## 边界与异常处理
- **数值边界**：[处理规则]
- **交互边界**：[处理规则]
- **状态边界**：[处理规则]
- **资源兜底**：图片失败降级为[方案]；音效失败[处理]
- **存档异常**：[处理规则]
```

## 9. 商业化设计
**必需内容：**
- 商业模式（买断制/免费+内购/广告变现）
- 付费点设计（如适用）
- 长期运营计划

**格式要求：**
```
## 商业模式
- **模式**：[买断制/免费+内购/广告变现/混合模式]
- **定价策略**：[说明]

## 付费设计（如适用）
- **付费点1**：[内容和定价]
- **付费点2**：[内容和说明]

## 运营计划
- **初期目标**：[目标]
- **长期规划**：[规划]
```

## 验证规则
- 必须包含第 1-8 章节（含第 8 章边界与异常处理）；第 9 章商业化设计可按需编写，开发计划由团队正式立项时再补
- 每个章节必需内容不能缺失
- 数值规模按玩法繁简取用，简单小游戏不强求重度数值；涉及的核心数值必须给出具体数值或计算公式
- 美术风格必须包含可执行的生成指引，并标明哪些资源用 Canvas/CSS/文字/emoji 替代、哪些需出图（PNG）
- 第 8 章须覆盖数值、交互、状态、资源加载与存档的边界兜底
- 文档字数按游戏复杂度调整，简单小游戏可更精简
